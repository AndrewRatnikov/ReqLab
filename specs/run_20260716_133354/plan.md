# Technical Plan: Migrate req-lab to a pnpm monorepo

**Run:** run_20260716_133354
**Date:** 2026-07-16

## Summary

req-lab moves from a single npm-managed package at the repo root to a pnpm workspace with the existing Vue app relocated to `apps/web`. A root `pnpm-workspace.yaml` and slimmed-down root `package.json` are added, npm's lockfile is dropped in favor of `pnpm-lock.yaml`, CI switches to pnpm, and a new Vitest suite verifies the workspace structure and that the app still builds from its new location.

## Approach

1. Create `pnpm-workspace.yaml` at the repo root declaring `apps/*` and `packages/*` as workspace members (`packages/*` unused today, reserved for future extraction — out of scope per PRD).
2. Move the app's existing files verbatim into `apps/web/`, preserving their relative structure and contents unchanged (no rewrites needed — Vite/TS configs use paths relative to their own file location, which doesn't change when the whole directory moves together):
   - `src/**` → `apps/web/src/**`
   - `public/**` → `apps/web/public/**`
   - `index.html` → `apps/web/index.html`
   - `vite.config.ts` → `apps/web/vite.config.ts`
   - `tsconfig.json`, `tsconfig.app.json`, `tsconfig.node.json` → `apps/web/tsconfig*.json`
   - `eslint.config.ts` → `apps/web/eslint.config.ts`
3. Split `package.json`: the app's own `package.json` (dependencies, devDependencies, and the `dev`/`build`/`preview`/`type-check`/`lint` scripts) becomes `apps/web/package.json` with `"name": "web"`. The root `package.json` becomes a thin workspace manifest with `"private": true`, no app dependencies, and scripts that delegate via `pnpm --filter web`, plus the new `vitest` devDependency and a `test` script for the migration-verification suite.
4. Delete `package-lock.json`. `pnpm-lock.yaml` is generated by running `pnpm install` (this happens naturally when the sandbox/CI runs `pnpm install`; the Coder does not hand-author the lockfile).
5. Update `.github/workflows/deploy.yml`: replace `actions/setup-node`'s npm cache + `npm ci`/`npm run build` with a pnpm setup (`pnpm/action-setup`) and `pnpm install`/`pnpm --filter web build`; update the upload-artifact `path` from `./dist` to `./apps/web/dist`.
6. Leave `.npmrc` (`min-release-age=7`) as-is — it's a registry-fetch setting pnpm also honors; not in scope to change.
7. Add a new root-level Vitest suite (`tests/monorepo-migration.test.ts`) that checks the workspace structure and re-uses the real scripts (via `child_process.execSync`, not mocked — this is an integration check of the actual migration, not unit logic, so the "no real fetch/axios without mock" contract rule doesn't apply since no network call is made).

**Edge cases the Coder must handle:**
- `apps/web/package.json`'s `"name"` must be exactly `"web"` — the root scripts and the test file's `pnpm --filter web ...` invocations depend on this exact name.
- Relative asset/config paths inside moved files must NOT be rewritten — only their location on disk changes.
- The root `package.json` must not retain any of the app's runtime dependencies (vue, primevue, etc.) — those belong solely to `apps/web/package.json`.

## Interface Contract

This section is the single source of truth for all names, paths, and file shapes. The Tester and Coder read this; neither invents anything independently.

### File: `pnpm-workspace.yaml` (repo root)
```yaml
packages:
  - 'apps/*'
  - 'packages/*'

onlyBuiltDependencies:
  - esbuild
  - '@parcel/watcher'

allowBuilds:
  '@parcel/watcher': true
  esbuild: true
```
**Revision note (post-sandbox):** pnpm 10+ blocks native build/postinstall scripts by
default (`ERR_PNPM_IGNORED_BUILDS`) for packages like `esbuild` and `@parcel/watcher`
that vite/vitest depend on transitively — without this allowlist, `pnpm install`
itself exits non-zero and nothing downstream (build, type-check, tests) can run.
This is a required part of a correct npm→pnpm migration, discovered when the test
sandbox's `pnpm install` failed. `onlyBuiltDependencies` is standard pnpm config;
`allowBuilds` additionally satisfies environments that wrap pnpm with a build-script
approval gate (e.g. a security scanner) — harmless if the wrapper isn't present.

### Test file: `tests/monorepo-migration.test.ts` (repo root, CREATE by Tester)
- **Test framework:** Vitest (`import { describe, it, expect } from 'vitest'`)
- **Imports allowed:** `vitest`; Node builtins `node:fs`, `node:path`, `node:child_process` (via `execSync`) — no other packages
- **No `data-testid` selectors apply** — this suite tests filesystem/config state and shell command exit codes, not rendered UI.
- **Structure and exact assertions** (Tester must implement all of these, and only these — no additional speculative tests):
  ```typescript
  import { describe, it, expect } from 'vitest'
  import { existsSync, readFileSync } from 'node:fs'
  import { execSync } from 'node:child_process'
  import { resolve } from 'node:path'

  const ROOT = resolve(__dirname, '..')

  describe('pnpm workspace structure', () => {
    it('declares apps/* as a workspace member in pnpm-workspace.yaml', () => {
      const contents = readFileSync(resolve(ROOT, 'pnpm-workspace.yaml'), 'utf-8')
      expect(contents).toMatch(/apps\/\*/)
    })

    it('has apps/web/package.json with name "web"', () => {
      const pkg = JSON.parse(readFileSync(resolve(ROOT, 'apps/web/package.json'), 'utf-8'))
      expect(pkg.name).toBe('web')
    })

    it('apps/web/package.json declares the expected scripts', () => {
      const pkg = JSON.parse(readFileSync(resolve(ROOT, 'apps/web/package.json'), 'utf-8'))
      expect(pkg.scripts).toMatchObject({
        dev: expect.any(String),
        build: expect.any(String),
        'type-check': expect.any(String),
        lint: expect.any(String),
      })
    })

    it('root package.json no longer lists app runtime dependencies', () => {
      const pkg = JSON.parse(readFileSync(resolve(ROOT, 'package.json'), 'utf-8'))
      expect(pkg.dependencies ?? {}).not.toHaveProperty('vue')
    })

    it('package-lock.json has been removed', () => {
      expect(existsSync(resolve(ROOT, 'package-lock.json'))).toBe(false)
    })
  })

  describe('build verification', () => {
    it('root "type-check" script delegates to the web app and succeeds', () => {
      expect(() =>
        execSync('pnpm run type-check', { cwd: ROOT, stdio: 'pipe' })
      ).not.toThrow()
    })

    it('root "build" script delegates to the web app and succeeds', () => {
      expect(() =>
        execSync('pnpm run build', { cwd: ROOT, stdio: 'pipe' })
      ).not.toThrow()
    })
  })

  describe('CI workflow', () => {
    it('deploy.yml installs and builds with pnpm, not npm', () => {
      const workflow = readFileSync(resolve(ROOT, '.github/workflows/deploy.yml'), 'utf-8')
      expect(workflow).toMatch(/pnpm\/action-setup/)
      expect(workflow).not.toMatch(/npm ci|npm run build/)
    })
  })
  ```
- **Dependencies:** `vitest` (root devDependency, pre-added — see note above)

**Revision note (post-review):** the original contract had the build/type-check tests call
`pnpm --filter web ...` directly, which never exercises the root `package.json`'s own
delegating scripts — criterion #7 (root scripts delegate correctly) would pass even if
those scripts were broken. Changed to invoke `pnpm run build` / `pnpm run type-check`
from root instead. Also added the CI workflow check for criterion #6, which had no test
at all. Both fixes made during Test-Reviewer stage, retry 1/2.

## Risks and open questions

- **Vitest pre-added to root `package.json` ahead of the Tester stage.** This deviates from strict test-first ordering (normally the Coder adds new dependencies), but is unavoidable here: the mechanical contract gate reads the target repo's *live* `package.json` to validate test imports, and this repo currently has zero test tooling. Pre-adding just the one line needed for the test file to type-check is the minimal fix; the Coder still does all real migration work.
- **`pnpm/action-setup` version pin.** The Coder should use a current stable major version tag (e.g. `v4`) and a `version` input compatible with the Node 24 runner already in use; exact pnpm version is the Coder's discretion as long as `pnpm install` succeeds.
- **Sandbox environment must have `pnpm` available** (via corepack or a global install) for the Vitest suite's `execSync('pnpm ...')` calls to succeed — this is an environment concern for Stage 6, not a code change.
